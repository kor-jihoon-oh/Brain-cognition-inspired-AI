# Mirror: 거울·빛 벤치마크

10×10 격자에서 거울과 스플리터를 배치해 두 센서에 목표 색의 빛을 보내는 벤치마크입니다. 총 **100문제 × 5라운드**이며, 라운드마다 광원·필터·센서의 위치, 규칙, 목표 색이 바뀝니다. 모델은 매 시도 제공되는 현재 배치와 센서별·전체 정오답 피드백으로 다음 제출을 결정합니다.

GPT-6.1 Sol, Claude Opus 5.5, Claude Sonnet 5.5를 같은 실행 코드로 지원합니다. 포함된 완료 결과는 **GPT-6.1 Sol 100문제, MPE 38.80%**입니다. 데이터셋과 모든 실험 결과 파일은 JSON으로 저장합니다.

## 구성

```text
mirror/
├── code/
│   ├── run_experiment.py   # 모델 선택, API 요청, 실행·중단·재개
│   ├── judge.py            # 제출 검사, 빛의 이동, 정답·지속적 오류 판정
│   ├── dataset.py          # 데이터셋 생성·검증
│   └── results.py          # 결과 저장·집계, API 사용량·비용 계산
├── dataset/
│   ├── private/           # 평가용 규칙·목표 색·정답 배치
│   ├── public_boards/     # 모델에 제공하는 라운드별 배치
│   ├── prompt.json        # {"language":"en","text":"영어 프롬프트 원문"}
│   ├── manifest.json      # 데이터 구성과 파일 해시
│   └── exclusivity-proof.json
└── result/
    └── 2026-10-28_16-50-18.540_KST/  # 포함된 100문제 결과
```

`private`는 모델에게 보내지 않는 평가자 정보를 뜻합니다. 해당 데이터와 정답 배치는 연구·검증을 위해 저장소에 공개되어 있습니다.

## 실행 준비

Python **3.10 이상**과 Python 표준 라이브러리만 사용합니다. 별도 패키지 설치는 필요하지 않습니다. 아래 명령은 `mirror` 폴더에서 실행합니다. 시스템의 Python 명령이 `python3`이면 `python` 대신 사용하세요.

```powershell
cd <저장소의-mirror-경로>
python --version
```

유료 실험에는 선택한 모델의 API 사용 권한과 키가 필요합니다. GPT는 `OPENAI_API_KEY`, Claude는 `ANTHROPIC_API_KEY` 환경변수를 사용합니다. 환경변수가 없으면 화면에 표시되지 않는 숨김 입력으로 키를 받습니다. 키와 인증 헤더는 결과 파일에 저장하지 않습니다.

## 실험 실행

인수 없이 실행하면 모델, T, k, 문제 범위, 추론 설정을 차례로 입력합니다.

```powershell
python code/run_experiment.py
```

설정을 명령에 지정하여 바로 실행할 수도 있습니다.

```powershell
python code/run_experiment.py --model sol --T 20 --k 2 --first 1 --last 100 --effort medium
python code/run_experiment.py --model opus --T 20 --k 2 --first 1 --last 100 --effort medium
python code/run_experiment.py --model sonnet --T 20 --k 2 --first 1 --last 100 --effort medium
```

위 명령은 각각 별도의 유료 실험을 시작합니다. 새 결과는 `result/날짜_시간_KST/`에 저장됩니다.

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--model` | `sol`, `opus`, `sonnet` 중 선택 | `sol` |
| `--T` | 라운드당 최대 채점 제출 수 | `20` |
| `--k` | 라운드 통과에 필요한 연속 정답 수 | `2` |
| `--first`, `--last` | 시작·마지막 문제 번호, 양 끝 포함 | `1`, `100` |
| `--effort` | 추론 설정: `low`, `medium`, `high`, `xhigh`, `max` | `medium` |
| `--max-output-tokens` | 추론을 포함한 총 출력 토큰 상한 | GPT: 요청에 생략, Claude: `128000` |
| `--timeout` | API 응답 대기 제한, 초 단위. `0`은 로컬 제한 없음 | `0` |
| `--clipboard` | Windows 클립보드에서 API 키 읽기 | 사용하지 않음 |

`1 ≤ k ≤ T`, `1 ≤ first ≤ last ≤ 100`을 만족해야 합니다. T·k·문제 범위를 바꾸어도 저장된 데이터셋은 바뀌지 않습니다. 모델 ID는 각각 `gpt-6.1-sol`, `claude-opus-5-5`, `claude-sonnet-5-5`입니다.

대화와 API가 반환한 추론 항목은 문제 안에서 유지하고 새 문제에서 초기화합니다. GPT의 암호화된 추론 항목과 Claude의 thinking·signature 항목을 후속 요청에 보존합니다. 캐시 사용량은 API가 보고한 실제 값으로 기록하며, 추론 토큰을 출력 토큰에 다시 더해 비용을 계산하지 않습니다.

## 중단 후 재개와 진행 확인

```powershell
# 특정 실행을 이어서 진행
python code/run_experiment.py --resume result/해당_실행_폴더

# 가장 최근 실행을 이어서 진행
python code/run_experiment.py --resume latest

# API 호출 없이 저장된 진행 상태만 확인
python code/run_experiment.py --inspect --resume result/해당_실행_폴더
```

재개할 때는 저장된 모델·T·k 등 설정을 사용합니다. 완료된 채점 제출을 다시 요청하지 않으며, 이미 완료된 실행은 API 호출 없이 종료합니다. 응답 저장 전에 끊긴 요청이나 미완료 응답은 같은 시도에서 다시 요청될 수 있습니다. API 오류·미완료 응답은 채점 제출 수에 포함하지 않습니다.

모델별로 여러 터미널을 사용할 때는 `latest`보다 해당 실행 폴더를 지정하는 것이 명확합니다. 같은 결과 폴더를 동시에 실행할 수 없으며, 저장된 데이터·프롬프트·코드의 해시가 다르면 재개를 거부합니다.

## API 없이 확인하기

```powershell
# 모델·실험 설정, 데이터와 첫 요청 점검
python code/run_experiment.py --model sol --T 20 --k 2 --dry-run

# 100문제의 배치와 500개 정답 경로 검증
python code/dataset.py verify --folder dataset

# 포함된 결과의 지표를 JSON으로 출력

# 저장된 응답으로 요청·채점·결과 일치 확인
python code/run_experiment.py --verify-results result/2026-10-28_16-50-18.540_KST

# 저장된 응답으로 집계 JSON 파일 다시 생성

```

위 명령은 API 키 없이 실행할 수 있습니다. `--verify-results`는 저장된 API 응답을 재채점하여 기록과 대조하고, `--rebuild`는 해당 실행의 집계 파일을 다시 씁니다. 모델을 다시 호출하는 작업은 아닙니다. `results.py`에서 `--run-folder`를 생략하면 가장 최근 실행의 요약을 출력합니다.

## 데이터셋 생성

```powershell
python code/dataset.py generate --folder dataset --workers 4
```

고정 시드 **2026102806**으로 후보를 생성하고 정답 경로를 탐색한 뒤 실제 시뮬레이션을 통과한 배치만 채택합니다. 같은 생성 코드와 시드로 공개된 100문제를 재현합니다. 기존 데이터가 생성 결과와 다르면 덮어쓰지 않고 중단하며, 동일한 기존 파일은 유지합니다. 다른 폴더를 지정하려면 먼저 그 폴더에 `prompt.json`을 준비하세요. `--workers`는 1–32이며 기본값은 4입니다.

생성 조건은 다음과 같습니다.

- 한 문제에서 다섯 규칙을 각각 한 번 사용하며 순서는 무작위입니다. 첫 라운드는 규칙별 20문제로 구성합니다.
- 광원·두 필터·두 센서는 매 라운드 이동합니다. 중앙 배치, 물체 사이 최소 거리, 특정 규칙끼리 연속하는 순서는 강제하지 않습니다.
- 광원은 격자 경계까지 남은 공간이 가장 큰 방향을 향하며, 동률이면 무작위로 선택합니다.
- 문제 안에서 두 센서의 목표 색 조합이 중복되지 않습니다. 필터 진입 방향 규칙에서는 흰색/흰색 목표를 사용하지 않습니다.
- 지정 구역은 2×2 칸이며 전체 격자를 25개 구역으로 나눕니다. 통과·금지 구역은 독립적으로 선택하고, 해당 라운드에는 광원·필터·센서가 없는 구역을 사용합니다.
- 정답 배치는 거울 4–5개와 스플리터 1개로 찾습니다. 모델 제출에는 배치 개수 제한이 없습니다.
- 회전·대칭·평행이동과 필터 색·센서 이름을 무시한 기하학적 중복을 제거합니다. 저장된 직전 정답 배치를 다음 배치에서 그대로 재사용해 정답이 되는 후보도 제외합니다.

규칙 순서와 목표 색은 배치 탐색 전에 정하며, 모델 실험 결과나 MPE로 데이터를 선별하지 않습니다. `exclusivity-proof.json`은 같은 현재 배치에서 직전·현재 조건의 동시 전체 정답 가능성을 검사한 기록입니다. 모든 직전 정답이 다음 규칙을 반드시 위반한다는 조건은 아닙니다.

## 모델 입력과 채점

모델 입력은 영어 [프롬프트](dataset/prompt.json)와 현재 배치의 `grid_size`, `source`, `filters`, `sensors`입니다. 매 시도 전체 배치를 제공하며, 규칙의 존재·종류, 지정 구역, 목표 색, 정답 배치는 입력에 포함하지 않습니다. 모델은 빈칸에 놓을 거울·스플리터의 전체 배치를 JSON 한 개로 제출합니다.

[judge.py](code/judge.py)는 좌표·종류·방향·물체 중복을 검사한 다음 광원 다음 칸부터 빛을 한 칸씩 이동시킵니다. 거울에서는 반사 방향으로, 스플리터에서는 직진과 반사의 두 경로로 진행합니다. 필터에 흰색 빛이 들어가면 해당 필터 색으로 바뀌고, 반대 색의 빛은 차단됩니다. `(행, 열, 방향, 색)`이 같은 상태를 다시 방문하면 중복 경로 처리를 종료합니다.

| 규칙 | 검사 내용 |
|---|---|
| 필터 좌우 진입 | 모든 필터 진입이 좌우 방향인지 확인. 위아래 진입은 차단하며 규칙 위반 |
| 필터 위아래 진입 | 모든 필터 진입이 위아래 방향인지 확인. 좌우 진입은 차단하며 규칙 위반 |
| 지정 구역 통과 | 광원 칸과 방문 경로에 지정 구역의 칸이 하나 이상 있는지 확인 |
| 지정 구역 통과 금지 | 광원 칸과 모든 방문 경로가 지정 구역 밖인지 확인 |
| 서로 다른 색 겹침 금지 | 광원·필터·센서 칸을 제외한 칸에 서로 다른 색이 함께 방문했는지 확인 |

필터를 전혀 지나지 않았다면 진입 방향 규칙 위반은 아닙니다. 센서는 목표 색 하나만 도달했을 때 정답이며, 빛 없음·다른 색·여러 색 도달은 오답입니다. 전체 정답은 두 센서 정답과 현재 규칙 충족을 모두 요구합니다.

피드백 형식 예시:

```json
{"sensor_results":{"S1":"correct","S2":"incorrect"},"result":"incorrect"}
```

센서별 판정은 현재 규칙하에서 실제로 추적한 빛을 기준으로 합니다. 두 센서가 정답이어도 전체 결과는 오답일 수 있습니다. 피드백에는 도달 색이나 실패 이유를 넣지 않습니다. 형식이나 배치가 유효하지 않은 제출은 센서별·전체 판정을 모두 `incorrect`로 반환합니다.

## 라운드 진행과 평가 지표

연속 정답 k회이면 라운드를 통과합니다. T회 안에 전체 정답이 한 번도 없으면 해당 라운드를 실패로 기록하고 남은 라운드를 미진행 처리합니다. 전체 정답은 있었지만 연속 k회에 미달했다면 실패로 기록한 뒤 다음 라운드로 진행합니다.

**지속적 오류**는 다음을 모두 만족하는 제출입니다.

1. 직전 라운드에서 전체 정답 제출이 한 번 이상 있었다.
2. 현재 제출의 형식과 배치가 유효하지만 현재 라운드에서는 전체 오답이다.
3. 같은 제출을 **현재 광원·필터·센서 배치에서 직전 규칙으로 다시 추적**했을 때 직전 규칙을 만족한다.

직전 목표 색은 사용하지 않습니다. 현재 규칙을 만족하더라도 목표 색을 틀리고 직전 규칙을 만족하면 지속적 오류에 포함됩니다. 이 판정은 제출한 배치에 대한 코드의 검사이며, 모델의 내적 의도를 판독하는 것은 아닙니다.

```text
라운드 PER = 지속적 오류 제출 수 / 실제 채점한 모든 제출 수 × 100
문제 MPE   = 해당 문제의 평가 가능한 R2–R5 PER 평균
전체 MPE   = 문제 MPE의 평균
```

PER 분모에는 정답과 일반 오답도 포함합니다. T회에 도달해 실패한 라운드도 평가 조건을 만족하면 포함합니다. R1, 미진행 라운드, 직전 라운드에 전체 정답이 없던 라운드는 PER 평균에서 제외하며 0으로 넣지 않습니다. 문제·전체 결과의 `per_percent` 필드는 각각 문제 MPE·전체 MPE입니다.

**Mean error**는 진행한 R1–R5의 오답률을 문제 안에서 평균한 뒤, 완료된 문제들의 평균을 계산한 값입니다. **N**은 MPE가 계산되는 문제 수 / 완료된 문제 수입니다. **API time**은 실제 API 요청 소요시간 합계로 요청 사이의 대기는 제외합니다. **Cost**는 저장된 토큰 사용량과 가격 스냅샷으로 계산한 추정액입니다. 확인할 수 없는 비용은 0으로 처리하지 않습니다.

## 결과 파일

각 실행은 API 요청·응답과 채점 정보를 JSON으로 저장합니다.

| 파일·폴더 | 내용 |
|---|---|
| `requests/*.json` | 인증 정보를 제외한 실제 API 요청 본문 |

| `progress.json` | 현재 진행 상태 |

| `transcripts/*.json` | 문제별 대화 기록. `text` 필드에 대화 원문 저장 |

`.gitignore`는 API 키 파일·환경 설정·임시 파일·새 실험 결과를 제외하고, 위 100문제 결과 폴더는 추적하도록 설정되어 있습니다. 추가 결과를 공개하려면 해당 폴더를 추적 예외에 넣으세요. `.gitattributes`는 해시 대상 파일의 줄바꿈 자동 변환을 막습니다. 저장된 요청·응답·스냅샷을 임의로 다시 포맷하면 해시 검증에 영향을 줍니다.
