# 과제 및 평가 방법

## 배치와 빛의 이동

격자는 10×10이며 좌표는 1부터 시작하는 `[행, 열]`입니다. 광원은 주어진 위치·방향에서 흰색 빛을 방출합니다. 빨간 필터와 파란 필터, 센서 S1·S2가 고정 물체이며 모델은 빈칸에 거울·스플리터를 배치합니다. 매 제출은 해당 응답에 포함된 전체 배치로 평가합니다.

`optics.py`는 광원 다음 칸부터 빛을 한 칸씩 이동시키며 `(행, 열, 방향, 색)` 상태를 추적합니다. 거울은 방향을 바꾸고 스플리터는 직진·반사 두 경로를 만듭니다. 같은 상태를 다시 만나면 중복 경로 처리를 종료해 순환을 막습니다. 센서에 도착하거나 격자를 벗어나거나 필터에서 차단되면 해당 경로가 끝납니다.

흰색은 필터 색으로 변합니다. 같은 색의 빛은 필터를 통과하며 다른 유색 필터에서는 차단됩니다. 센서는 목표 색 하나만 받은 경우 정답입니다. 빛 없음, 다른 색, 여러 색의 동시 도달은 오답입니다.

## 규칙

문제마다 다음 다섯 규칙을 각각 한 라운드씩 사용합니다. 큰 범주로는 필터 진입 방향, 지정 구역, 서로 다른 색 겹침의 세 종류입니다.

| 규칙 | 실제 코드의 검사 |
|---|---|
| 필터 좌우 진입 | 모든 필터 진입 방향이 left/right인지 검사. 위아래 진입은 해당 경로를 차단하고 규칙 위반 처리 |
| 필터 위아래 진입 | 모든 필터 진입 방향이 up/down인지 검사. 좌우 진입은 해당 경로를 차단하고 규칙 위반 처리 |
| 지정 구역 통과 | 광원 칸과 방문한 경로 칸 중 지정 구역의 칸이 하나 이상 있는지 검사 |
| 지정 구역 통과 금지 | 광원 칸과 모든 방문 경로 칸이 지정 구역 밖인지 검사 |
| 서로 다른 색의 빛 겹침 금지 | 고정 물체 칸을 제외한 일반 칸에서 서로 다른 색이 함께 방문했는지 검사 |

필터에 전혀 도달하지 않은 경로는 진입 방향 규칙 위반이 아닙니다. 단, 해당 규칙의 목표 색은 적어도 하나가 유색이므로 전체 정답에는 필터 통과가 필요합니다. 같은 색끼리의 겹침은 허용합니다.

현재 생성기의 지정 구역은 2×2 칸, 총 25개(A–Y)입니다. 해당 통과·금지 라운드의 지정 구역에는 광원·필터·센서가 없습니다. 다른 라운드까지 그 구역을 비우는 조건은 없습니다.

## 모델 입력과 피드백

모델은 [영어 프롬프트](../dataset/prompt_en.txt)와 현재 배치의 `grid_size`, `source`, `filters`, `sensors`만 받습니다. 매 시도 배치를 제공합니다. 규칙의 존재·종류, 지정 구역, 목표 색, 정답 배치는 모델 입력에서 제외합니다.

```json
{"sensor_results":{"S1":"correct","S2":"incorrect"},"result":"incorrect"}
```

위는 피드백 형식 예시입니다. 센서별 판정은 현재 규칙하에서 실제로 추적한 빛과 목표 색을 비교한 값입니다. 전체 판정은 두 센서 정답과 현재 규칙 충족을 모두 요구합니다. 두 센서가 정답이어도 전체 판정은 오답일 수 있습니다. 실제 색과 실패 이유는 피드백에 포함하지 않습니다. 유효하지 않은 제출은 두 센서와 전체가 모두 `incorrect`입니다.

## 지속적 오류와 MPE

라운드 r에서 직전 라운드에 전체 정답 제출이 한 번 이상 있었을 때 PER를 계산합니다. 연속 2회 통과 여부와는 별개의 조건입니다.

지속적 오류는 다음을 모두 만족한 제출입니다.

1. 제출 형식과 배치가 유효하다.
2. 현재 라운드에서는 전체 오답이다.
3. 동일한 제출을 **현재 광원·필터·센서 배치**에서 직전 규칙으로 다시 추적했을 때 직전 규칙을 만족한다.

직전 목표 색은 사용하지 않습니다. 현재 규칙을 만족해도 목표 색이 틀리고 직전 규칙을 만족하면 지속적 오류일 수 있습니다. 나머지 오답은 일반 오답입니다. 이 분류는 출력된 배치의 규칙 만족 여부를 평가하며 모델의 내적 의도를 직접 측정하지 않습니다.

```text
PER(i,r) = 지속적 오류 제출 수 / 실제 채점한 모든 제출 수 × 100
MPE(i)   = 문제 i의 계산 가능한 R2–R5 PER 평균
전체 MPE = MPE가 정의되는 문제들의 MPE 평균
```

정답 제출도 PER 분모에 포함합니다. T=20에서 실패한 라운드도 실제 시도가 있고 평가 대상이면 포함합니다. R1, 미진행 라운드, PER를 정의할 수 없는 라운드는 제외하며 0으로 넣지 않습니다. 결과 파일의 문제·전체 `per_percent`는 각각 문제 MPE·전체 MPE를 나타냅니다.

평균 오답률은 각 진행 라운드의 모든 오답/제출 비율을 문제 안에서 평균하고, 그 문제별 평균을 전체 완료 문제에 대해 평균합니다. R1도 포함합니다. 제출 수를 모두 합친 오답 비율과는 다릅니다.

## 라운드 종료

- 연속 정답 2회이면 라운드 통과.
- 20회 안에 정답이 한 번도 없으면 실패로 끝내고 그 문제의 남은 라운드는 미진행 처리.
- 정답은 있었지만 연속 2회에 못 미치면 실패로 기록하고 다음 라운드 진행.
- 새 문제에서는 대화를 초기화.

## 생성과 검증

`generate_dataset.py`가 시드 2026102806으로 100문제를 생성합니다. 각 문제의 규칙 순서와 목표 색 조합은 배치 탐색 전에 정합니다. 한 문제에 목표 조합 중복은 없고, 필터 방향 규칙에는 흰색/흰색 조합을 쓰지 않습니다. 첫 라운드는 다섯 규칙별 20문제로 균형을 맞춥니다.

광원·두 필터·두 센서는 매 라운드 이동합니다. 위치·거리·규칙끼리 인접하는 순서에 추가 제한을 두지 않습니다. 광원은 격자 경계까지 남은 공간이 가장 큰 방향을 향하며 동률이면 무작위로 정합니다. 통과·금지 구역은 독립적으로 추출합니다.

후보마다 거울 4–5개와 스플리터 1개를 사용하는 정답 경로를 탐색하고 실제 시뮬레이션으로 확인합니다. 이는 정답의 존재 증명이며 최소 기물 수나 동일한 체감 난이도를 뜻하지 않습니다. 모델 제출의 기물 수 제한은 없습니다.

500개 배치는 회전·대칭·평행이동과 필터 색·센서 이름을 무시한 기하학적 중복을 제거합니다. 저장된 직전 정답 배치를 새 배치에 재사용했을 때 현재 정답이 되는 후보도 제외합니다. 모델 실험 결과나 MPE를 보고 데이터를 선별하지 않습니다.

`exclusivity-proof.json`은 동일한 현재 배치에서 이전·현재 규칙과 목표를 각각 평가했을 때의 **동시 전체 정답 배제**에 관한 기록입니다. 모든 이전 정답이 다음 규칙을 위반한다는 증명이나 실제 서로 다른 두 배치 사이의 완전 배타성 주장은 아닙니다.

|---|---|
| `start_gpt_with_key.py` | 명령행, 키 입력, 시작·재개 |

| `experiment.py` | 요청 작성, 시도·라운드·문제 상태 전환 |
| `protocol.py` | 공개 배치 및 제출 JSON 스키마 |
| `optics.py` | 배치 검증, 광선 추적, 규칙·색·PER 판정 |
| `api.py`, `cost.py` | HTTP 전송·중단, 키 마스킹, 저장 단가로 비용 추정 |
| `storage.py` | JSON·CSV·HTML 보고서와 지표 집계 |
| `dataset_validation.py`, `proof_checker.py` | 데이터·정답·증명 검사 |

| `serialization.py` | 요청·응답 JSON의 일관된 직렬화와 값 처리 |
